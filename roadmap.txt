# TRUTH-SURFACE DOCTRINE (architectural rule — never violate)

Argus has three truth classes:

  1. Canonical execution truth
     orders, fills, account, positions, decision events

  2. Deterministic lifecycle truth
     trade lifecycle records rebuilt from canonical truth (trade_journal)

  3. Analytical truth
     latency, slippage, attribution, equity curves, risk metrics, reports

Rules:
  - lower layers feed higher layers only
  - higher layers never mutate lower layers
  - analytics must never become hidden runtime control state
  - every derived metric must be traceable to its source artifact

## Phase 16 — Unattended Operations Hardening

Goal:
Run hands-off under normal conditions without operator babysitting.
Phase 16 is only valid after Phase 15 exists — you need visibility
before you remove yourself from the loop.

Focus:
  * supervisor/watchdog process (auto-restart runner on crash with backoff)
  * health checks (feed staleness, adapter heartbeat, fill latency, invariant violations)
  * safe-mode and degraded-mode runtime:
    - full mode (normal operation)
    - no-new-entry mode (hold existing, no new positions)
    - reduce-only mode (exits allowed, entries blocked)
    - observation-only mode (log only, no orders)
    - reconciliation-only mode (startup integrity check, no trading)
  * auto-throttle (reduce position size on consecutive losses or anomalous slippage)
  * config freeze per run (config hash stored in run manifest, changes require new run)
  * run manifests (run_id, config hash, code hash, start time, artifact list)
  * artifact integrity checks on startup (hash verification)
  * alerting via existing Discord webhook:
    - HALT events
    - recovery contradictions
    - drawdown limit breach
    - invariant failures
    - fill anomalies
  * daily automated backup (ops/backup_repo.ps1 already exists)
  * daily restore drill (automated, logged)
  * safe-mode trigger conditions:
    - feed divergence
    - fill latency > threshold
    - abnormal slippage (> p99)
    - drift threshold breach
    - invariant failure
    - state mismatch

Invariant engine (continuous, not just on startup):
  * positions match fills
  * realized PnL matches lifecycle truth
  * order/fill linkage is complete
  * no duplicate lifecycle closure
  * timestamp ordering is valid
  * cash/exposure limits hold
  If critical invariant fails: halt entries, preserve state, alert, enter safe-mode

Exit:
  * normal operation needs no manual babysitting
  * abnormal operation escalates deterministically via alert
  * system fails closed, not open
  * promotions and config changes remain human-governed
  * unattended runtime is auditable from artifacts alone
