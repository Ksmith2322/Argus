# GOVERNING PRINCIPLES (read before every decision)

  1. Built != Verified != Operational != Promotion-trusted.
     Code existing is not the same as code trusted under failure.
     A test suite existing is not the same as coverage being sufficient.
     A dashboard panel existing is not the same as the data behind it being clean.

  2. Operational completeness is not evidence of economic edge.
     Infrastructure maturity must never be confused with strategy maturity.
     You cannot build your way to profitability. You must trade your way there.

  3. Only validation-lane runners may accumulate promotion evidence.
     Observation-lane and exploration-lane runners collect data.
     Data collection is not the same as cohort validation.

  4. A killed deployment may preserve a dormant thesis.
     Kill the deployment. Archive the thesis. Retire the config.
     Do not resurrect under the same conditions.
     But if venue, cost, or regime assumptions change materially,
     the thesis may be re-evaluated from scratch with a new config.

  5. Config hash freeze is mandatory once a cohort starts.
     Any config change mid-cohort invalidates all prior trades.
     No exceptions. No "I only changed one thing."

# TRUTH-SURFACE DOCTRINE (architectural rule -- never violate)

Argus has three truth classes:

  1. Canonical execution truth
     orders, fills, account, positions, decision events, decision_trace

  2. Deterministic lifecycle truth
     trade lifecycle records rebuilt from canonical truth (trade_journal)

  3. Analytical truth
     latency, slippage, attribution, equity curves, risk metrics, reports

Rules:
  - lower layers feed higher layers only
  - higher layers never mutate lower layers
  - analytics must never become hidden runtime control state
  - every derived metric must be traceable to its source artifact
  - machine-local artifacts (ops/logs/) are non-canonical analytical surfaces
    unless explicitly promoted into git-tracked or shared truth

# MATURITY TAXONOMY (every component carries exactly one status)

  BUILT:              Code exists, compiles, basic smoke test passes.
  VERIFIED:           Tested under adversarial/edge-case conditions. Failure modes documented.
                      A VERIFIED component must have:
                        - named test set with case count
                        - failure classes covered (enumerated)
                        - last execution date
                        - whether pass was deterministic or observational
                        - known blind spots acknowledged
  OPERATIONAL:        Running in production context. Monitored. Recovery tested.
                      For execution-truth-adjacent components (reconciliation, state
                      persistence, recovery): requires observed correct behavior under
                      at least one real fault, not just simulated fault.
                      For reporting/dashboard: requires running and monitored.
  PROMOTION-TRUSTED:  Has earned the right to inform capital decisions.
                      Requires: 30+ valid trades, divergence guard PASS,
                      artifact divergence CLEAN, kill discipline PASS.

  No component may borrow credibility from a higher-maturity sibling.
  A BUILT dashboard does not make a BUILT strategy OPERATIONAL.

  BUILT governance logic is advisory until it has observed at least one real
  watch/kill/degrade event correctly. Implementation is not the same as
  demonstrated correct behavior under real violation.

# STRATEGY STATUS LABELS (every runner carries exactly one)

  HYPOTHESIS:         Idea stage. No backtest.
  BACKTEST-PASS:      Positive expectancy in backtest. Payoff Contract defined.
  PAPER-VALIDATING:   Live paper runner accumulating cohort trades.
  PAPER-PASS:         30+ valid trades, all promotion criteria met.
  LIVE-VALIDATING:    Real capital, micro size, accumulating live fills.
  LIVE-PASS:          30+ live fills, slippage within model, expectancy holds.
  SCALED:             Full position sizing, proven edge.
  KILLED:             Deployment killed. Thesis archived. Config retired.
  DORMANT:            Thesis preserved, deployment stopped. Awaiting venue/regime change.

  "Collecting data" is not a status. Use one of:
    HYPOTHESIS (no backtest yet, just telemetry)
    BACKTEST-PASS (backtested, no valid cohort)
    PAPER-VALIDATING (below minimum sample)
    DORMANT (post-kill diagnostic shadow-run)

  "Blocked" is not a status. Execution blockers are a separate field:
    Status: HYPOTHESIS  |  Blocker: No Paxos subscription
    Status: DORMANT     |  Reactivation: venue fees < 20bps

# GLOBAL INVARIANTS (binding contracts -- every system, every strategy)

## Payoff Contract (strategy-specific, not universal)

  Every strategy must define before paper trading begins.
  Thresholds below are DEFAULT PRIORS. Strategy-specific contracts
  may override if the economic case is documented and signed off.

  Default priors:
    - Target reach rate:  kill if < 25%  (override: fat-tail strategies may go lower)
    - Timeout rate:       kill if > 60%  (override: time-decay strategies may go higher)
    - Stop rate:          kill if > 2x target rate  (override: depends on payoff asymmetry)
    - MFE tail check:     median MFE must exceed 1.5x cost
    - Costs from day one: all backtests and paper runs include realistic fees,
      spread, and slippage. No "add costs later" allowed.

  If a strategy overrides a default prior, the override must state:
    - which threshold is being relaxed
    - what the strategy-specific threshold is
    - why the relaxation is economically justified
    - what alternative kill signal replaces the relaxed one

  Template:
    Strategy: _______________
    Venue/Pair: _______________
    Min target move: _______________
    Expected target reach rate: _____ % (default kill < 25%)
    Expected timeout rate: _____ % (default kill > 60%)
    Expected stop rate: _____ % (default kill > 2x target rate)
    Median MFE vs cost: _____ x (kill < 1.5x)
    RT cost model: _____ bps/pips
    Overrides: _______________

## Execution Contract
  Every strategy must define:
    - Venue and instrument
    - Fee structure (maker/taker, per-side, RT total)
    - Spread model (median, P95, widening conditions)
    - Slippage model (expected vs worst-case)
    - Fill rate (% of signals that execute)
    - Latency budget (signal-to-fill target)

## Kill Discipline
  - Payoff Contract fail = kill deployment. No exceptions, no "one more week".
  - Execution delta > 25% vs model = kill deployment.
  - 3 consecutive weeks negative with >= 15 trades/week = kill deployment.
  - Drawdown > 3x model (paper) or > 2x model (live) = kill deployment.
  - Kill = deployment archived. Config retired. Name retired for that config.
  - Thesis may be preserved as DORMANT if kill reason is venue/cost/regime specific.
  - DORMANT thesis requires: documented kill reason, explicit reactivation conditions,
    and a fresh config + cohort if ever revisited.

## Phase C Rollback Rules
  - ONE variable per cycle. Never two simultaneous experiments.
  - Minimum 5 days or 20 signals per cycle (whichever comes first).
  - Revert if EV drops > 20% vs baseline.
  - No simultaneous experiments across strategies within same system.
  - Max active configs per strategy family: 1 (no silent config drift).
  - New config invalidates previous cohort. Period.

## Anti-Overfitting Rules
  - Config hash freeze mandatory once cohort starts.
  - No parameter reuse across OOS segments without disclosure.
  - Walk-forward segmentation required: train on period A, validate on period B.
  - Stress suite must include adversarial scenarios, not just historical replay.
  - Regime coverage minimum: strategy must be tested across trending, ranging,
    and volatile regimes before paper promotion.
  - Data provenance: every backtest must record data source, date range,
    and whether any filtering/cleaning was applied.

# PROMOTION PIPELINE (Research -> Paper -> Live -> Scale)

## Research -> Paper gate:
  - Payoff Contract defined and passing in backtest
  - 7/7 stress suite pass (gap, spread spike, news, low liquidity, trending,
    ranging, overnight). Stress suite must be adversarially generated.
  - 14+ days of backtest data minimum
  - 100+ signals in backtest
  - Walk-forward validation (no same-period train + test)
  - Data provenance documented
  - Regime coverage: trending, ranging, volatile all represented

## Paper -> Live gate:
  - 30+ valid paper trades (noisy evidence, not proof)
  - Expectancy within 20% of backtest expectancy
  - Replay-Live Divergence Guard passes (outcome + state-space)
  - All promotion_gate.py checks PASS
  - Kill discipline PASS
  - Artifact divergence CLEAN
  - Governance component trust rule: any BUILT component feeding promotion
    decisions must have been manually cross-checked against source truth
    at least once before its output is treated as gate-passing evidence.
    Automated output from untested-by-reality components is advisory only.

## Live -> Scale gate:
  - 30+ live fills
  - Slippage within model bounds
  - Expectancy within 30% of paper expectancy

## DEMOTION paths:
  - Live -> Paper: on 20% expectancy degradation (watch trigger, not instant kill)
  - Scale -> Live: on drawdown > 1.5x model

# REPLAY-LIVE DIVERGENCE GUARD

  Purpose: Detect when paper/live execution diverges from backtest assumptions.

  Layer 1 — Outcome divergence (BUILT, OPERATIONAL):
    - Signal frequency ratio (live vs replay): KILL < 0.5 or > 2.0, WATCH < 0.7 or > 1.5
    - Win rate delta (10+ trades): KILL > 20pp, WATCH > 15pp
    - Timeout rate (15+ trades): KILL > 60%
    - Stop/target ratio (15+ trades): WATCH if stop > 2x target

  Layer 2 — State-space divergence (BUILT, needs validation):
    - Feature distribution shift (range_pct, vol_z live vs replay means)
    - Session participation mismatch (which hours are trades happening)
    - Trigger composition by regime (are entries concentrated in one regime)
    - Spread/volatility context mismatch

  Implementation:
    Layer 1: argus_flow/ops/divergence_guard.py (OPERATIONAL)
    Layer 2: argus_flow/ops/signal_analyzer.py (BUILT, manual review)

  Output: argus_flow/logs/divergence_report.json
  Dashboard: /api/divergence_status endpoint + IBKR Fleet widget

# GLOBAL RISK BUDGET

  Allocation limits:
    - Max single system allocation: 50% of capital (paper), 70% (live)
    - No single strategy > 80% of trailing 30-day PnL

  Correlation budget:
    - EUR/USD + GBP/USD count as 1.5 systems, not 2 (correlated USD risk)
    - JPY crosses share a combined drawdown limit
    - Correlated pairs share a combined drawdown limit

  Per-system drawdown limits:
    - > 3x model = pause (paper)
    - > 2x model = pause (live)
    - > 1.5x model = reduce scale 50%

  ML Governor rules:
    - Never primary decision path. Advisory only.
    - LOG_ONLY until proven incremental over deterministic rules.
    - Retrain requires 30+ single-config trades. Mixed-config training forbidden.
    - FX retrain pipeline: BUILT. Waiting for trade data. (retrain_governor_fx.py)

# THE SCALING PATH

  Phase 1 (NOW):  Prove EV (paper) -- validation-lane runners accumulating trades
  Phase 2:        Prove execution (micro live) -- real capital, real fills, real slippage
  Phase 3:        Prove stability -- N trades with bounded drawdown within model
  Phase 4:        Scale capital into proven edges
  Phase 5:        Add systems (only after current systems are profitable)

  Rule: stacking proven edges and scaling capital into them > adding more systems
  Rule: no phase transition without explicit gate passage. No shortcuts.
